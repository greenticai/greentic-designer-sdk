# PR 02 — Add generic artifact-producing DesignExtension fixture

## Repository

`greenticai/greentic-designer-sdk`

## Objective

Add a generic scaffold fixture, and optionally a `gtdx new` template, proving that a DesignExtension can produce artifacts through the existing `tools.invoke-tool` WIT interface.

This must not be Sorla-specific. It should produce a generic sample artifact and validate the artifact output convention added in PR 01.

## Current contract

The DesignExtension WIT already exposes `tools`, `validation`, `prompting`, and `knowledge` exports. The artifact fixture should only rely on `tools.list-tools` and `tools.invoke-tool`:

```wit
interface tools {
  record tool-definition {
    name: string,
    description: string,
    input-schema-json: string,
    output-schema-json: option<string>,
  }
  list-tools: func() -> list<tool-definition>;
  invoke-tool: func(name: string, args-json: string) -> result<string, extension-error>;
}
```

This PR demonstrates the artifact convention without requiring a WIT change.

Current descriptor invariant to preserve: a plain `DesignExtension` has no `runtime.gtpack`. `DesignExtension` descriptors may include `runtime.gtpack` only when they also contribute non-empty `contributions.nodeTypes`. This fixture is about tool-generated artifacts, so it should not add descriptor-level `runtime.gtpack` unless it is specifically a node-providing design extension.

## Fixture scope

Use the repo’s existing scaffold/template layout. If this should be available through `gtdx new`, add a new scaffold kind in `crates/greentic-extension-sdk-cli/src/scaffold/mod.rs`, wire it into `crates/greentic-extension-sdk-cli/src/scaffold/template.rs`, and add the template under:

```text
crates/greentic-extension-sdk-cli/templates/design-artifact-producer/
```

If it is only test fixture data, keep that data in `greentic-extension-sdk-testing`; there is no current root-level `fixtures/` directory, and unreferenced directories under `templates/` are not picked up by the current `include_dir!` loader.

## Tool exposed

The fixture should expose:

```text
generate_artifact
```

Input schema:

```json
{
  "type": "object",
  "required": ["name"],
  "properties": {
    "name": { "type": "string" },
    "kind": { "type": "string", "default": "example" }
  }
}
```

Output JSON follows the generic `ArtifactToolOutput` shape from PR 01:

```json
{
  "artifacts": [
    {
      "kind": "example",
      "filename": "example-artifact.json",
      "media_type": "application/json",
      "sha256": "...",
      "bytes_base64": "..."
    }
  ],
  "diagnostics": [],
  "preview_json": {
    "title": "Example artifact",
    "summary": "Generated by fixture"
  }
}
```

## `gtdx` validation

Use the fixture’s `output-schema-json` to advertise the artifact output schema. Extend `gtdx validate` only if the existing validation path can inspect the static descriptor or schema files. Do not require live execution of the WASM extension; this SDK does not currently provide a generic WASM invocation path in `gtdx validate` or `gtdx doctor`.
