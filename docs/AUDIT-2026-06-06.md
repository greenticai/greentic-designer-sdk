## TL;DR

The audit-remediation arc since cycle 1 is **real and rigorous**: all 3 cycle-1 P0s are closed, the
sign→pack→manifest→wasm chain is sound (constant-time digests, unconditional integrity even under `Loose`,
size caps, zip-slip + path-traversal guards, HTTPS-by-default both transports, 0600 secrets, anchored
authenticity via `verify_describe_with_key`). Clippy is clean.

Two things still bite:

1. **NEW — HIGH: describe-substitution on the Store path.** The describe that is authenticated + consented
   (from `/metadata`) is **not** the describe that gets extracted to disk (from the archive). They are never
   compared, and `describe.json` is deliberately excluded from the manifest ledger. A malicious/compromised
   Store can ship a benign signed describe for consent while installing an archive whose on-disk
   `describe.json` declares broader permissions. Exploitability depends on whether the **runner** grants
   capabilities from the on-disk describe (out of this repo) — but the SDK should not decouple them.

2. **OPEN regression — P1: v1→v2 migration of `DeployExtension` produces an undeserializable v2 doc.**
   Migration unconditionally hoists `targets`→`execution`, but `DescribeJson::try_from` forbids `execution`
   for non-Bundle kinds. The masking test only asserts `dropped_keys`, never round-trips.

Everything else is P2/P3 hardening and housekeeping.

## 2. Fresh findings @ 1.2.6-research

### P0 / HIGH

**H1 — Describe-substitution on the Greentic Store install path** · *verified by hand*
`registry/src/store.rs:231-271`, `registry/src/lifecycle.rs:64-66,282-306`, `contract/src/manifest.rs:87,179`

`store.rs::fetch` builds `ExtensionArtifact.describe` from the `/metadata` endpoint and `bytes` from the
separate `/artifact` endpoint. `install` then authenticates and prompts consent on **`artifact.describe`**
(the metadata one). `verify_integrity` binds `metadata.describe.manifestSha256` → archive `manifest.json` →
all archive files — **but `describe.json` is deliberately excluded from the manifest ledger**
(`manifest.rs:87,179`, with a regression test locking the exclusion in). `extract_to_staging` then writes the
archive's **own** `describe.json` to disk. Nothing asserts `archive describe.json == metadata.describe`.

Attack: a malicious/compromised Store serves a benign, correctly-signed describe via `/metadata` (consent =
e.g. no network/secrets) while the artifact's internal `describe.json` declares broader permissions. The
signed wasm is unchanged (it *is* bound via the manifest), so this is not arbitrary-code-injection — it is a
**permission/declaration mismatch**: the runtime reads the on-disk describe, which was never consented to or
authenticated. Under `Loose`, authenticity is skipped entirely, making it trivial.

Contrast: `local.rs::fetch` and `oci.rs::fetch` parse describe **from the archive**, so they don't have this
seam — only the Store path does.

**Fix:** make the authenticated describe and the extracted describe the same object. Either (a) in
`verify_integrity`/`install`, read `describe.json` out of `artifact.bytes` and assert byte-equality with the
authenticated describe, or (b) drop the `/metadata` describe for install and parse + authenticate the
archive's describe like the local/OCI paths do. (Severity escalates to P0 if the runner grants capabilities
from the on-disk describe — confirm with greentic-start/runner.)

## 3. Verified-correct (the strong parts — no action)

- **Sign/verify core:** JCS canonicalization strips `.signature` identically on sign + verify; `verify_strict` (rejects malleable sigs / small-order keys); `verify_describe_with_key` requires `asserted == trusted` byte-for-byte before verifying (no TOCTOU). (`contract/src/signature.rs`)
- **manifestSha256 binding** closes the swap-wasm attack: manifest is a signed describe field; `bind_manifest` runs before `sign_describe`. Archive bomb/cap defenses (bounded `take(cap+1)`, decompressed-byte caps, O(1) lookup, reject smuggled + missing). (`contract/src/manifest.rs`)
- **Integrity unconditional, constant-time, on both transports**; `Loose` waives signature only and warns. (`registry` `store.rs`/`oci.rs`/`lifecycle.rs`/`digest.rs`)
- **HTTPS-by-default + correctly-scoped opt-in escape hatch** (non-http schemes rejected even with opt-in; token never crosses cleartext for the configured URL). **256 MiB download cap.** **TOFU pinning** verifies signature before pinning; Strict never auto-pins; RMW under exclusive lock + atomic save.
- **state crate fully remediated:** lock created-once / never-unlinked, `tmp→write→fsync→rename→fsync(parent)`, RMW inside the lock. (`state/src/atomic.rs`, `state.rs`)
- **testing M6/M7:** provider fixtures fully `Result`-based; mocks enforce declared host/secret permissions (denied attempt recorded; `PermissionDenied` ≠ `NotFound`).
- **CLI:** path-traversal closed in pack producer + signing-key id; one canonical PKCS8-PEM key format; no command injection (all `Command::new().arg()`, no shell); `gtdx verify` correctly distinguishes anchored vs integrity-only and hard-fails a stripped ledger.
- **Packaging:** embedded WIT byte-identical & build.rs-generated; release publish order correct (contract→state→testing→registry→cli); `-research` tags excluded from crates.io; no committed build artifacts. **Clippy clean.**
- `#![forbid(unsafe_code)]` at every crate root.
