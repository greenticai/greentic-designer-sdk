# greentic-designer-sdk — Audit & Review

**Branch:** `research` · **Version:** `1.2.0-research` · **Date:** 2026-06-01
**Scope:** all 5 crates (contract, state, registry, testing, cli) + WIT specs + workspace hygiene
**Baseline:** `cargo clippy --workspace --all-targets --locked -D warnings` → **clean (exit 0)**

Findings below were produced by 5 parallel reviewers and the two release-blocking P0s were
re-verified by hand against the code. Line refs are accurate as of the commit above (`ac60fe7`).

---

## TL;DR

The crate compiles clean and the **sign/verify core is sound**, but the v2 migration (`ac60fe7`,
PR #6) shipped without finishing the blast radius:

1. **Scaffold templates were never migrated to v2** → `gtdx new → dev → publish` is dead for every kind.
2. **The v1→v2 migrator drops the WASM component path** and **produces unparseable docs for Deploy+targets** — both masked by tests that never deserialize the migrated output.
3. **No artifact-bytes integrity check anywhere in the install path** — a tampered `.gtxpack` installs cleanly; `TrustPolicy::Loose` skips everything.

Three P0s, all release-blockers for the research line. Details + fixes below.

---

## P0 — Release blockers

### P0-1 — Scaffolded projects can't `dev` or `publish` (v1 templates vs v2-only deserializer)
**Files:** `crates/greentic-extension-sdk-cli/templates/{design,bundle,deploy,provider}/describe.json.tmpl`; consumers `cli/src/publish/mod.rs:276-281`, `registry/src/local.rs:102-103`; contract `src/describe/mod.rs:22-30`, `src/compat.rs:7-13`.

All four `describe.json.tmpl` still emit v1 shape: `apiVersion: greentic.ai/v1`, `$schema: …/describe-v1.json`, singular `runtime.component`, and **no `compat` block**. Verified by reading the template.

The publish + dev-install paths do `validate_describe_json(value)` then `from_value::<DescribeJson>(value)`:
- `validate_describe_json` dispatches on `apiVersion` and validates a v1 doc against the **looser v1 schema → passes**.
- `DescribeJson` is the **v2-only** struct: `compat` is required (no serde default), `#[serde(deny_unknown_fields)]`, and `runtime` expects a `components` map — so `runtime.component` is an unknown field. **Deserialization fails.**

No migration runs in the dev/publish paths (`migrate_v0_4_x_value` is only wired into consumer `build.sh`; `gtdx migrate` is unimplemented). Net: every `gtdx new` project dies at the first `dev`/`publish` with a confusing serde error *after* schema validation falsely reports success.

**Fix:** Migrate the 4 templates to v2 (`apiVersion: greentic.ai/v2`, `describe-v2.json`, add `compat`, `runtime.components: { main: { oci_ref|gtpack, sha256, world } }`; provider keeps `gtpack`). Add a `render → from_value::<DescribeJson>` round-trip test per kind. Make `validate_describe_json` **reject** a `greentic.ai/v1` apiVersion outright instead of down-validating.

### P0-2 — v1→v2 migration silently drops `runtime.component` (the WASM path)
**File:** `contract/src/migration.rs:94-133` (`migrate_runtime` / `build_component_entry`)

`build_component_entry` reads **only `gtpack`**; it never reads `runtime.component` (the required v1 artifact ref, e.g. `"extension.wasm"`). Empirically reproduced: migrating a v1 fixture with `runtime.component = "extension.wasm"` yields `main: { oci_ref: "placeholder://zero", sha256: 0…0 }` — the real path is gone. Since `gtpack` isn't even in the v1 schema, **most v1 extensions lose their only component reference** and become un-publishable placeholders, with no hard error.

**Fix:** In `build_component_entry`, when there's no `gtpack`, carry `rt.get("component")` into the v2 entry. Add a migration test asserting the v1 `component` value survives into v2 (current tests never check this).

### P0-3 — Downloaded artifact bytes are never integrity-verified; `Loose` skips all checks
**Files:** `registry/src/store.rs:165-185`, `registry/src/oci.rs:101-140`, `registry/src/lifecycle.rs:136-143`; contract `src/signature.rs:86`.

`fetch()` downloads the `.gtxpack`, parses `describe.json`, and returns the bytes **without hashing them against `metadata.artifact_sha256`** — which `store.rs` even has in hand and discards. OCI ignores the layer digest too. Signature verification (`verify_describe`) only covers the JCS-canonicalized `describe.json`, **not the artifact bytes**. And `TrustPolicy::Loose => Ok(())` skips signature checks entirely. So a tampered/corrupt artifact installs cleanly; the inner provider-gtpack digest (`provider_install.rs:63-85`) is self-certified by the same (untrusted) describe.

**Fix:** In `store.rs::fetch` and `oci.rs::fetch`, compute `artifact_sha256(&bytes)` and compare (constant-time) against the manifest/metadata digest **unconditionally** (integrity ≠ authenticity) before use; return a new `IntegrityMismatch` error on mismatch. Make `Loose` waive only the *signature*, not the digest, and `tracing::warn!` when it does.

## P2 — Medium

- **`cli/src/publish/mod.rs:310-335`** — signing never re-verifies the signature it just produced before upload; a JCS/key drift only fails at the consumer. Re-verify after `sign_describe`.
- **`registry/src/local_publish.rs:60-84`** — `publish_local` writes client-supplied `artifact_sha256` without recomputing over the bytes (not CLI-exploitable today, but the registry is a library). Recompute or reject on mismatch.
- **`cli/src/commands/doctor.rs:100`** — `.expect("reqwest client")` panics in the exact diagnostics command meant to run on broken machines. Handle the `Err`.
- **`cli/src/scaffold/embedded.rs:28`** — `.expect("embedded wit filename")` on `gtdx new` path (forbidden construct). `filter_map` instead.
- **`registry/src/lifecycle.rs:106-128`** — zip-slip guard relies on deprecated `mangled_name()`; use `enclosed_name()` + canonicalize-under-staging check; no symlink/abs-path defense.
- **`registry/src/storage.rs:66-75`** — `commit_install` `remove_dir_all` then `rename` is non-atomic: a crash in the window leaves the slot empty. Rename old → `.bak` first, restore on failure.
- **`state/src/atomic.rs:43-45`** — `write_atomic` unlinks the lock file while semantically held → two writers can lock different inodes and interleave (last-writer-wins drops an update). **Stop removing the lock file**; optionally fsync the parent dir for crash-durability. (Data write itself — tmp+fsync+rename — is correct.)
- **`registry` local/oci `fetch`/`publish`** — synchronous `std::fs` + full-archive zip parsing on async worker threads; wrap in `spawn_blocking`.
- **`cli/src/dev/mod.rs:116-166`** — Ctrl+C not observed during an in-progress `cargo build` (cancel token only polled between 250ms `recv_timeout` slices). `spawn_blocking` + `select!` on `cancel.cancelled()`.
- **CI gap** — `ci/local_check.sh` + `ci.yml` only `cargo publish --dry-run` contract+state; testing/registry/cli publishability regressions surface only at release time. Add `--dry-run` for testing (+registry/cli). Also add `--all-features` to clippy+test to match canonical Greentic pattern (currently `--locked` only).
- **`templates/*/Cargo.toml.tmpl`** — `wit-bindgen-rt` split (`0.35` design/bundle/deploy/provider vs `0.36` wasm-component; dx-cleanup plan targeted `0.41`). Pin all to one version aligned with the assumed `cargo-component`.
- **`cli/src/commands/publish.rs:34`** — `--trust` accepts arbitrary strings (`--trust banana` succeeds, recorded in receipt); and `trust_policy` appears to gate nothing in publish — only labels the receipt. Make it a `value_enum`; confirm whether it should affect verification.
- **`cli/src/publish/mod.rs:304-307`** — `dist/publish-staging.gtxpack` left behind after successful publish. `remove_file` after canonical copy.

## Verified-correct (no action)

- **Sign/verify canonicalization is consistent** — both `sign_describe`/`verify_describe` strip `.signature` and JCS-canonicalize the identical typed struct; verify operates on exactly the signed bytes.
- **Newtypes** (`Sha256`, `Locale`, `ComponentId`, `CapabilityId`) validate in both `FromStr` and `Deserialize` — can't construct an invalid one. `SignatureAlgorithm ↔ "ed25519"` mapping correct + exhaustive match (PR #6 fix is sound).
- **`pack_writer` determinism** (sorted entries, zeroed timestamps, CRLF→LF text-only) — correct + tested.
- **`packer.rs` assets fix holds** — `assets/` included with regression test `build_pack_includes_icon_assets_dir`; pack is deterministic.
- **`builder.rs` target probe robust** — `cargo metadata --no-deps`, searches wasip2+wasip1, surfaces build failures with exit codes.
- **`watcher.rs`** — excludes `dist/`+`target/`, no infinite rebuild loop; debounced; tested.
- **`template.rs`** — `bail!`s on any unsubstituted `{{placeholder}}`; all 11 tokens populated.
- **`local_publish` publish is atomic** (temp + `sync_all` + rename) with advisory exclusive lock.
- **Internal deps exact-pinned** `=1.2.0-research`; `release.yml` publish order correct (testing before registry).
- **Edition 2024 / Rust 1.95 uniform** across all crates; `rust-toolchain.toml` pins `1.95.0` + `wasm32-wasip2`.
- **Embedded `1.2.0-research` WIT byte-identical** to canonical `wit/`; cross-world base types consistent.

1. **P0-1** templates → v2 + round-trip test (unblocks the whole DX loop).
2. **P0-3** unconditional artifact-digest verification in `store.rs`/`oci.rs`; `Loose` waives signature only.
3. **P0-2** carry `runtime.component` through migration + test.
4. **P1-1 / P1-2** Deploy+targets parseable; publish enforces v2 schema.
5. **P1-4 / P2 doctor** remove the two production `expect` panics.
6. Housekeeping: README WIT version, `git rm embedded-wit/0.4.4`, delete untracked `0.5.0-pre.1/`, CI `--all-features` + dry-run coverage.
